## この課題で学ぶこと

### まず覚える「4 つの場所」

Git の操作は、変更が次の 4 つの場所を移動していくだけです。

```
① 作業中のファイル ──＋ボタン──▶ ② ステージ ──コミット──▶ ③ 自分の PC の履歴 ──プッシュ／同期──▶ ④ GitHub
                                                         ③ 自分の PC の履歴 ◀──────プル────── ④ GitHub
```

| 場所 | 中身 | 次の場所へ送る操作 |
| --- | --- | --- |
| ① 作業中のファイル | 編集して**保存**した状態 | ＋ボタン（ステージ） |
| ② ステージ | 次のコミットに含めると決めた変更 | コミット |
| ③ 自分の PC の履歴 | コミットした記録（まだ自分の PC の中だけ） | プッシュ／変更の同期 |
| ④ GitHub | インターネット上の記録 | プル（③ へ取り込む） |

各ミッションは、「どの場所で、どんな操作をするのか」を 1 つずつ体験できるように並んでいます。

### ミッションの構成

| ステージ | Mission | 体験すること | わかるようになること |
| --- | :---: | --- | --- |
| 1. 基本の流れ | **1** | コミット＆プッシュ | ①→②→③→④ を一周して、GitHub に反映される |
| 1. 基本の流れ | **2** | 変更の破棄（Discard） | ① の段階なら、変更をなかったことにできる |
| 2. ブランチ | **3** | ブランチの作成と切り替え | 切り替えるとファイルが消えたり復活したりする＝「並行世界」 |
| 2. ブランチ | **4** | ローカルでのマージ | 並行世界の変更を `main` に合流させる |
| 3. チーム開発 | **5** | プルリクエスト（PR）とプル | ブランチ → PR → GitHub でマージ → 手元に**プル**（④→③）という実務の流れ |
| 4. トラブル対処 | **6** | コミットの取り消し（Revert） | プッシュ済みの間違いを、履歴を壊さず打ち消す |
| 4. トラブル対処 | **7** | マージコンフリクトの解消 | 同じ行がぶつかったとき、どちらを残すか自分で選ぶ |
| 4. トラブル対処 | **8** | `.gitignore` で機密情報を守る | API キーなどを GitHub に上げない方法 |

## STEP 0：事前準備

> **場所：** 自分の PC　／　**ゴール：** ツールがそろい、Git に名前が登録されている

### 1. ツールをインストールする

| ツール | 入手先 | メモ |
| --- | --- | --- |
| **VS Code** | [code.visualstudio.com](https://code.visualstudio.com/) | 日本語で使う場合は、拡張機能「Japanese Language Pack for Visual Studio Code」を入れて再起動 |
| **Git** | [git-scm.com](https://git-scm.com/) | Windows はインストーラーの設定をすべて初期値のままで OK |
| **GitHub アカウント** | [github.com](https://github.com/) | 無料で登録 |

### 2. Git に名前とメールアドレスを登録する（最初の 1 回だけ）

コミットには「誰が変更したか」が記録されます。その記録に使う名前を登録します。

1. VS Code を開きます。
2. メニューの **ターミナル → 新しいターミナル**（Terminal → New Terminal）で、画面下にターミナルを出します。
3. 次の 2 行を **1 行ずつ** 貼り付けて <kbd>Enter</kbd> を押します。`あなたの名前` などは自分のものに置き換えてください。

```
git config --global user.name "あなたの名前"
git config --global user.email "GitHubに登録したメールアドレス"
```

> [!NOTE]
> これは「コミットに記録する名前」の登録で、**GitHub へのログインとは別物**です。ログインは STEP 2 で行います。

## STEP 1：自分用のリポジトリを作る

> **場所：** ブラウザ　／　**ゴール：** GitHub 上に「あなた専用のコピー」ができている

1. ブラウザで GitHub にログインし、このリポジトリのページを開きます。
2. 右上の緑色のボタン **「Use this template」→「Create a new repository」** をクリックします。
3. 次のように設定します。

   | 項目 | 設定 |
   | --- | --- |
   | Include all branches | 初期状態（**Off**）のままで OK |
   | Repository name | 好きな名前（例: `my-git-practice`） |
   | 公開範囲 | **Private** |

4. **「Create repository」** をクリックします。

> [!TIP]
> これで「あなた専用のコピー」が GitHub 上にできました。以降はこのコピーで自由に練習してください。他の人の作業とぶつかることはありません。

## STEP 2：サインインしてクローンする

> **場所：** VS Code　／　**ゴール：** VS Code のエクスプローラーに `README.md` や `MISSIONS.md` が表示されている

STEP 1 で作ったリポジトリは **Private（非公開）** なので、VS Code から GitHub に**ログイン（サインイン）**しないと取り込めません。クローンの途中でサインインする流れになっています。

1. VS Code で <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd>（Mac は <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>P</kbd>）を押し、コマンドパレットを開きます。
2. `Git: クローン`（`Git: Clone`）と入力して選びます。
3. 候補から **「GitHub から複製」**（Clone from GitHub）を選びます。
4. **GitHub へのサインイン**を求められます。
   1. 「拡張機能 'GitHub' が GitHub を使用してサインインしようとしています」→ **「許可」**（Allow）
   2. ブラウザが開く → GitHub にログイン → **「Authorize Visual Studio Code」** などの緑のボタンで許可
   3. 「Visual Studio Code を開きますか？」→ **「開く」** で VS Code に戻る
5. 自分のリポジトリの一覧から、STEP 1 で作ったもの（例: `あなたのID/my-git-practice`）を選びます。
6. 保存先のフォルダーを選ぶと、クローンが始まります。
7. 右下の「クローンしたリポジトリを開きますか？」→ **「開く（Open）」**
   - 「このフォルダー内のファイルの作成者を信頼しますか？」と出たら **「はい、作成者を信頼します」** を選びます。

✅ 左側のエクスプローラーに `README.md` や `MISSIONS.md` が表示されていれば成功です。

> [!TIP]
> **サインインできたか確かめるには：** VS Code の左下にある人型のアイコン（アカウント）をクリックすると、サインイン中の GitHub アカウント名が表示されます。

<details>
<summary><b>「GitHub から複製」が出ない場合</b>（クリックで開く）</summary>

1. 自分のリポジトリのページで緑の **「Code」** ボタンを押し、URL（`https://github.com/...git`）をコピーします。
2. 手順 3 で、候補を選ぶ代わりに URL を貼り付けて <kbd>Enter</kbd> を押します。
3. 「Git Credential Manager」という小さな画面が出たら **「Sign in with your browser」** を選び、ブラウザでログインします。

</details>

## STEP 3：ミッションを進める

> **場所：** VS Code　／　**ゴール：** `MISSIONS.md` 最後のチェックリストがすべて埋まっている

1. VS Code のエクスプローラーで **[`MISSIONS.md`](MISSIONS.md)** をクリックします。
   - 見出しや表が整った**読みやすい表示（プレビュー）**で開きます。
   - `#` や `|` などの記号だらけの表示で開いた場合は、<kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>V</kbd>（Mac は <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>V</kbd>）を押すと読みやすい表示になります。
2. 作業しながら手順を読みたいときは、`MISSIONS.md` の**タブを画面の右半分へドラッグ**すると、左右に並べて表示できます。
3. Mission 1 から順番に進めてください。

### 進め方のコツ

| コツ | 理由 |
| --- | --- |
| 各ミッション最後の **「✅ 確認ポイント」を必ず確かめる** | 変更が「4 つの場所」のどこまで届いたかを見るのが、いちばんの学びになります |
| ソース管理の **「グラフ」（Graph）を時々見る** | Mission 3〜7 では、履歴の線が枝分かれしたり合流したりする様子が見えます |
| 詰まったら `MISSIONS.md` の **「困ったときは」** を見る | よくあるエラーと対処をまとめています |
| 最後の **チェックリストがすべて埋まったら修了** | — |
